# 本项目路由引擎

引擎由本项目实现，采用 Python 标准库及系统 curl。配置生成器与引擎共用节点排序，并生成私有探测映射，不需要单独安装控制器工程或额外运行时。

## 工作流程

1. 从回环管理 API 获取当前 Selector、候选及连接信息。
2. 读取完整 HTTPS 响应体，并校验状态与响应结构。默认使用 ChatGPT 的公开 trace 与 robots 路径；这不等同于账号登录、Codex 业务或长流成功。
3. 当前路径持续失败或近期失败达到阈值时，按新鲜证据和近期质量选择候选。活跃时降低后台探测数量，仍轮转探索冷候选。
4. 候选通过三轮独立入口验证，再通过一次即时复核，才写入选择器。
5. 写入前持久化事务；切换后通过正式代理入口复核三轮。失败则回滚；检测到外部选择或配置代际变化时丢弃证据，优先保留外部结果。
6. 进程重启时协调未完成事务；无法确认接口状态时保留事务记录，等待恢复，不盲目覆盖。

## 保护与限制

- 私有映射绑定配置摘要；正常服务同时检查核心进程身份及探测端口归属。映射或本地入口失效不计入节点惩罚。
- 后台维护两个热备候选并保留冷候选探索。热备就绪要求连续成功、至少 45 秒证据跨度及最近 90 秒的新鲜证据；热备也必须重新通过切换验证。
- 隔离为 5、15、30 分钟递增，同一期内不反复延长；长期连续健康后降低等级。
- 每轮恢复最多验证三个候选，预算 90 秒；单次请求有独立超时，整轮可能超出预算一个在途请求的时间。取消和基础设施变化不会伪装成节点故障。
- 同一个用户、管理地址与代理组只允许一个后台引擎实例。只读 `--once`／`--shadow` 不修改选择器或持久状态。
- 不删除存量连接，不读取用户 Cookie 或账号令牌，不提供 macOS／Windows 部署集成，也不声称网络探测能保证全部业务成功。

状态保存在私有的 `controller/route-state.json`，日志写入 journal 及可选轮转文件。损坏状态会阻止自动写入，请保留备份后排查；分享日志前仍需检查节点显示名。
