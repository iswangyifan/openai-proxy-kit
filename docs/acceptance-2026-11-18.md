# 0.3.0 发行验收记录

日期：2026-11-18。结论：本轮覆盖的 Ubuntu 24.04 / GNOME / amd64 场景通过，可以供同事在该环境试用。GitHub 的远端 CI、Release 上传及发布后重新下载校验仍须执行。

## 环境与方法

- 使用独立 KVM 虚拟机，Ubuntu 24.04.5，内核 6.8.0-147-generic，2 vCPU、4 GiB 内存。
- 基础镜像来自 Ubuntu 官方 noble cloud image；下载后与其 SHA256SUMS 核对，摘要为 `04e8f2461a16a44e78a370284471f29616cdd9baf1893df25807b71f985b6c94`。
- 安装 GNOME Shell 46、GTK 4.14.5、libadwaita 1.5、Python 3.12。GNOME 在虚拟 Wayland 显示器运行，GUI 调用真实业务实现，没有替换启停、状态查询或日志模块。
- 应用仅通过 `.deb` 安装；虚拟机不挂载开发仓库，没有 Node、Git 或额外控制器工程。仅单独复制验收脚本及私有测试订阅。
- 使用独立用户和会话总线；没有修改宿主机代理、DNS、应用启动器或服务。

## 本轮发现并修复

1. systemd 将带双引号的 EnvironmentFile 路径判为非绝对路径并忽略，路由服务因此缺少环境变量、反复重启。修正模板，并用实际 systemd 解析器增加回归。
2. 配置流程吞掉路由引擎安装失败，可能误报成功。改为失败退出；启动引擎失败时在设置系统代理前回滚。
3. 已适配启动器再次开启时重复注入失败。增加恢复记录与文件摘要检查，使重复开启保持幂等，同时保留被手工修改的文件。
4. 实际 mihomo 无连接时返回 `connections: null`，中断故障恢复循环。按空连接集合处理，并增加对应回归。
5. root 维护脚本生成 Python 字节码，导致卸载留下包目录。禁用维护脚本字节码写入，并通过 py3clean 清理旧缓存；实际 PackageKit 卸载复验目录已移除。

## 验收边界

- 已验证上面的具体环境；其他发行版、架构、桌面及实体显示硬件未认证。
- ChatGPT 公开网络端点和 Codex 实际请求已验证；没有自动操作 ChatGPT 网页/桌面版的账号登录、验证码或完整对话流程。
- 网络与账号服务状态、节点可用性会变化。本次通过不保证所有订阅、地区、公司内网或后续时刻均可用。
- 远端 GitHub Actions、仓库保护、公开下载地址及下载后复验，需要在维护者推送和创建 Release 后完成。

## 复跑入口

默认安全回归执行 `bash tests/check.sh`。真实发行验收脚本为 [vm_acceptance.py](../tests/vm_acceptance.py) 和 [desktop_live_acceptance.py](../tests/desktop_live_acceptance.py)，仅在带 `/etc/opk-acceptance-vm` 标记且主机名以 `opk-acceptance` 开头的可丢弃虚拟机中执行。它们会改变该虚拟机内的代理、服务和用户文件，不应在工作电脑上创建标记来绕过保护。

VM 脚本通过 `~/accept/subscription.yaml` 接收私有测试订阅，结果写入 `~/accept/results.json`。不要提交测试订阅、完整原始日志、SSH 密钥或虚拟机磁盘。发行步骤见[发布流程](releasing.md)。
